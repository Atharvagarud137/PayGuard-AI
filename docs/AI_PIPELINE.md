# PayGuard-AI: AI assistance roadmap (deferred)

**Status: deferred.** The project pivots first to a deterministic Payment Integration Reliability Lab. This document describes a later, conditional AI phase. It is not an implementation plan for the current 30-day work.

## Principle

AI must consume structured evidence generated by deterministic scenario execution. It is advisory only. It must not authorize, decline, capture, settle, refund, mutate payment state, autonomously run generated code or replace assertions.

## Preconditions

AI work should not start until these exist and are demonstrated:
- Scenario execution and replay.
- Deterministic assertion engine.
- Structured, sanitized evidence and event timelines.
- Ambiguous-outcome, retry/idempotency and webhook scenarios.
- A reproducible report format.
- A curated evaluation dataset with known outcomes.

## Possible later capabilities

1. Evidence-grounded failure summaries.
2. Failure-category classification.
3. Root-cause hypotheses labeled as unverified.
4. Suggested additional scenarios in a validated schema.
5. Similar historical run retrieval only if evaluation shows retrieval materially helps.
6. Human feedback and evaluation metrics.

## Proposed bounded workflow

```text
Deterministic scenario run
       |
       v
Structured evidence + assertions
       |
       v
Schema validation and redaction
       |
       v
AI summarization/classification (optional)
       |
       v
Evidence references + confidence/limitations
       |
       v
Human review
```

The AI output must distinguish observed facts, hypotheses and recommendations. Every factual assertion should point to the structured evidence it used. Unsupported explanations are a failure, not an acceptable fluent answer.

## Evaluation

Before release, evaluate on a curated set of scenario failures and measure:
- Failure-category accuracy.
- Evidence-supported root-cause quality.
- Unsupported-claim/hallucination rate.
- Suggested scenario validity and duplicate rate.
- Human acceptance rate.
- Investigation-time reduction.

Do not set arbitrary accuracy targets before building the evaluation dataset and baseline.

## Technology decision

No AI framework, embedding database or local model is selected yet. Avoid prematurely committing to LangChain, LangGraph, ChromaDB, embeddings, Ollama or agent frameworks. Choose the simplest implementation that meets evaluated requirements; a direct model API or local model wrapper may be sufficient.

## Safety and privacy

- Synthetic data only.
- Redact secrets and card-like values before AI processing.
- No production payment credentials or real cardholder data.
- No generated executable code as an automatically trusted artifact.
- Scenario suggestions require schema validation and human approval.
- Deterministic scenario verdicts remain authoritative.

## Status

All AI features described here are future possibilities. The current implementation has no AI RCA, retrieval or AI-generated test pipeline.
